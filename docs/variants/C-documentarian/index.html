VARA · MAINNET

Read any program on Vara, without a registry.

A Sails program is a WASM actor on Gear Protocol that carries its own interface description inside the binary — in a custom section named sails:idl. This explorer reads that section straight from the chain, then decodes every call, query, event, and error against it. No off-chain ABI database. No verification step. The chain is the source of truth.

What's an interface_id?

Every #[service] in a Sails program gets a deterministic 64-bit fingerprint computed from its canonical IDL. Two services with the same public surface produce the same id, on any chain, any compiler.

On the wire, the first 8 bytes of every message after the "GM" magic identify which service inside the program is being addressed. The explorer uses it to look up the right ABI without guessing.

What's a route_idx?

A service exposes an ordered list of exported functions. The route_idx is just the position of the called function in that list — one byte, zero-based.

Combined with interface_id it pins exactly one function, even when functions are renamed, reordered between deploys, or shared across services. We resolve it against the IDL embedded in the program's WASM at the moment of decode.
